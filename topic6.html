📝 Interrupt-Driven I/O Topic 6

The 1-Sentence Story: Interrupt-driven I/O solves the inefficiency of polling by letting I/O devices alert the CPU via hardware signals only when they need service, allowing the CPU to perform useful computation and overlap I/O with processing.

📌 Definitions & Key Terms

Interrupt
A hardware signal generated by an I/O device to alert the processor that it requires service.
ISR
Interrupt Service Routine: the special routine executed by the CPU in response to an interrupt request.
Interrupt Latency
The time between receiving an interrupt request and starting execution of its ISR.
INTR
The interrupt-request control line used by devices to signal the CPU.
Interrupt Nesting
A higher-priority interrupt is allowed to interrupt the ISR of a lower-priority device.
Vectored Interrupt
The interrupting device supplies an identifying code (vector) so the CPU can directly find the correct ISR.
Daisy Chain
Devices share an INTR line; the INTA signal propagates through devices in a chain. The device closest to the CPU has highest priority.
Exception
An internal event (error, illegal instruction, privilege violation) that disrupts normal execution and transfers control to a service routine.

🔌 Interrupt Hardware

🔹 Shared Line & Open-Collector Outputs

  • Multiple devices share a single INTR line.
  • Open-Collector/Open-Drain outputs allow multiple devices to pull the line LOW (0) without conflict. A pull-up resistor keeps the line HIGH (1) when idle.
  • The CPU must then determine which device interrupted (via polling, vectored interrupts, or daisy chaining).

💾 Saving Processor State

🔹 Context Preservation

  • The CPU must preserve: Program Counter (PC) (address of next instruction, i+1), Processor Status (PS) (condition flags, IE bit), and register contents.
  • The ISR ends with a Return-from-Interrupt instruction, which restores the saved state and resumes at instruction i+1.

🔘 Enabling / Disabling Interrupts

IE = 1 Interrupts enabled.
IE = 0 Interrupts disabled.
  • The Interrupt-Enable (IE) bit in the processor status register controls interrupt acceptance.
  • Used to protect critical instruction sequences and ISR execution.
  • Processors may automatically disable interrupts when entering an ISR and restore the previous state on return.

⬆️ Priority and Nesting

🔹 Priority Scheme

  • A priority scheme determines which interrupt gets serviced first (High > Low).
  • When the CPU starts an ISR, its priority is raised to that of the device.
  • A higher-priority device can interrupt a lower-priority ISR (nesting).

🔍 Identifying the Interrupting Device

Polling

ISR checks status registers of devices one by one.

slow

Vectored Interrupts

Device supplies a vector code → CPU directly finds ISR address.

fast

Daisy Chaining

INTA propagates through devices; closest device with a request blocks INTA and supplies its vector. Priority is fixed by physical position.

fixed priority

🔹 Priority Groups

  • Multiple priority lines combined with daisy chaining within each group for flexibility.

🎛️ Interrupt Controller

🔹 Dedicated Hardware

  • Hardware that receives requests, determines the highest-priority one, masks/enables selected interrupts, and provides interrupt information (vector) to the processor.

⚠️ Exceptions (Key Types)

Error Recovery: Memory errors, illegal instructions, division by zero.
Debugging: Trace (exception after every instruction), Breakpoint (Trap/software interrupt).
Privilege Exception: User program attempts to execute a privileged instruction (executable only in supervisor mode).
📌 EXAM POINT

Polling: CPU waits and wastes time. Interrupt: CPU does useful work, device alerts CPU when ready (overlapping computation and I/O).

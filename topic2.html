📝 Bus Performance & Architecture Topic 2

The 1-Sentence Story: To prevent the shared bus from becoming a performance bottleneck or suffering from signal collisions, modern computers use separate buses for memory and I/O, and rely on bus arbitration to manage access among multiple bus masters.

📌 Definitions & Key Terms

Bus Bottleneck
A condition where the bus cannot transfer data fast enough to keep up with the connected components (e.g., a fast CPU waiting on a slow bus).
Bus Contention
A situation where multiple bus masters request the bus simultaneously, reducing performance due to the time required to resolve the conflict.
Bus Arbitration
The process of determining which bus master is allowed to use the bus next, preventing simultaneous access and data corruption.
Arbiter
The hardware (often the CPU or a dedicated circuit) that selects the next bus master based on a priority scheme.

⚡ Factors Affecting Bus Performance

Bus Width

Number of data lines (wider = more bits per cycle).

Bus Clock Frequency

Speed of transfers (higher frequency = faster transfers).

Transfer Protocol

How devices coordinate (Synchronous vs. Asynchronous).

🏗️ Bus Architecture Comparison (Exam Favorite)

🧠 Processor‑Memory Bus

  • Length: Short (on the same board).
  • Timing: Synchronous (high‑speed clock).
  • Nature: Proprietary, matched to memory access characteristics.
  • Goal: Maximum speed.

🔌 I/O Bus (Peripheral Bus)

  • Length: Longer (devices may be meters away).
  • Timing: Asynchronous (handshaking).
  • Nature: Follows established standards (USB, PCI).
  • Goal: Flexibility and compatibility across varying device speeds.

🔄 Arbitration Process

  1. Masters request the bus.
  2. The Arbiter selects one master (based on priority).
  3. The selected master receives access and performs the transaction.
  4. The bus is released for the next master.
🔒 GOLDEN RULE

Arbitration guarantees only one bus master is active at a time — eliminating collisions and ensuring fair, priority‑based access.

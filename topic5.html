📝 Parallel I/O & Program-Controlled Transfer Topic 5

The 1-Sentence Story: Parallel I/O uses interface circuits with data and status registers to connect devices to the bus, but program-controlled I/O forces the CPU to wastefully "poll" (repeatedly check) the device status until it is ready to transfer data.

📌 Definitions & Key Terms

I/O Interface
Circuitry that connects an I/O device to the bus, providing address decoding, data buffering, status flags, and timing control.
Port
The device side of the I/O interface (e.g., a Parallel Port or Serial Port).
Program-Controlled I/O
The processor controls the I/O operation explicitly through program instructions (checking status, waiting, and then transferring data).
Polling
The process where the processor repeatedly checks an I/O device's status flag to see if it is ready.

🧩 Interface Registers (Exam Favorite)

DATAIN

Holds input data from the device. Read by the CPU.

DATAOUT

Holds output data from the CPU to be sent to the device.

Control Register

Configures interface settings (e.g., baud rate, data format).

SIN Status Input: 1 = Data available to read; 0 = No new data.
SOUT Status Output: 1 = Device ready to accept data; 0 = Device busy/not ready.

🖥️ Parallel Port Operation

⌨️ Keyboard Input Example
  1. Key pressed → Encoder generates code.
  2. Code is loaded into DATAIN.
  3. SIN flag is set to 1 (data available).
  4. CPU checks SIN, reads DATAIN, and SIN clears to 0.
🖨️ Printer Output Example
  1. Printer is ready → asserts Idle signal.
  2. Interface sets SOUT flag to 1.
  3. CPU checks SOUT, writes data to DATAOUT.
  4. Loading DATAOUT clears SOUT to 0.
  5. Interface asserts Valid signal → printer accepts data.
  6. Printer finishes → asserts Idle again.

🔄 Polling (Key Concept)

Check Status → Is Device Ready? → (No) Check Again → (Yes) Transfer Data
⚠️ Major Disadvantage (CPU Time Wastage): The CPU is occupied in a loop checking the status flag instead of performing useful computation. It must wait for the slow I/O device.
📌 EXAM POINT

Memory transfers are predictable (data is always ready), but I/O devices are unpredictable. Program-controlled I/O uses polling to handle this unpredictability, but at the cost of CPU efficiency.

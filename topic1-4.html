Topic 4: Serial I/O & Transmission

Subtopic 4.1: Serial I/O Basics & Serial vs. Parallel Transfer

Step 1: The Core Concept & Analogy
The Engineering Problem:
The CPU processes data in parallel (e.g., 32 bits or 64 bits at a time). However, sending 32 bits simultaneously over a long wire is expensive and impractical—it requires 32 separate wires, and signals can interfere with each other over distance. How do we send data to devices that are far away or only have a single wire?

The Real-World Analogy:
Imagine you need to move 8 boxes from your house to a friend's house down the street.
Parallel Transfer: You hire 8 people, and each carries one box at the same time. It's incredibly fast, but you need 8 people (8 wires), and they all have to walk side-by-side on a very wide road (expensive and difficult over long distances).
Serial Transfer: You hire 1 person who carries the boxes one at a time, walking back and forth. It takes longer, but you only need 1 person (1 wire) and a narrow path. It's much cheaper and works over long distances.

Step 2: The Technical Definition

Serial I/O:

  • Data is transmitted one bit at a time over a single communication line.
  • Requires fewer wires than parallel transfer.
  • Convenient for connecting devices that are physically far from the computer.
  • Transmission speed is specified as a bit rate (bits per second).
  • Inside the computer, data is parallel. On the device side, data is serial. The conversion is done using shift registers.

Parallel Transfer:

  • Transfers multiple bits simultaneously (e.g., 8, 16, or 32 bits at once).
  • Requires multiple data lines.
  • Suitable for communication within a computer and over short distances.
  • Faster than serial, but more expensive and prone to signal interference over long distances.

Key Difference (Exam Point):
Serial: One bit at a time.
Parallel: Multiple bits at the same time.

Step 3: What is a Shift Register?

A shift register is a small, temporary storage unit made of a row of flip-flops (memory bits). It has two key abilities:

  • Parallel Load: It can grab all the bits from the computer's data bus at once (e.g., 8 bits simultaneously).
  • Serial Shift: It can push those bits out one by one, in a line, through a single wire, every time the clock ticks.

How it helps here:
Think of a shift register like a loading dock with a conveyor belt.
The CPU dumps a whole pallet of 8 boxes (parallel data) onto the dock at once.
The conveyor belt (the shift register) then moves the boxes onto the truck one at a time (serial data) to send down the single road.
In reverse (receiving), boxes come in one at a time and get stacked up until there are 8, then the CPU grabs the whole stack at once.
This perfectly solves the mismatch between the CPU's parallel nature and the long-distance serial wire.

Subtopic 4.2: Asynchronous Serial Transmission (Start/Stop Bits)

Step 1: The Core Concept & Analogy
The Engineering Problem:
When you send data serially, the receiver needs to know when a character is starting and when it ends. If you just send a stream of 1s and 0s, the receiver has no idea where one character ends and the next begins, especially if the line is idle for a long time between characters.

The Real-World Analogy:
Imagine someone is sending you letters through a mail slot, but they don't use envelopes. They just shove a piece of paper through. You wouldn't know where one letter ends and the next begins.
To fix this, they start every message with the word "START" and end it with "STOP".
When the line is quiet (idle), you just wait.
The moment you see "START", you know a new message is coming.
After you read the message, you wait for "STOP" to know it's over.

Step 2: The Technical Definition

Asynchronous Serial Transmission (specifically Start-Stop Transmission):

  • The transmitter and receiver use independent clocks (not synchronized to each other). They must just have the same nominal frequency (baud rate).
  • Data is organized into small groups (typically 6–8 bits).
  • A character is framed with a Start bit and Stop bit(s):
    • Idle State: The line is held at logic 1.
    • Start Bit: A logic 0. The transition from 1 to 0 alerts the receiver that a character is about to arrive.
    • Data Bits: The actual character information (typically 5-8 bits).
    • Parity Bit (Optional): For error checking.
    • Stop Bit(s): Logic 1 (1 or 2 bits), indicating the end of the character.

Synchronization (The Receiver's Trick):

  • The receiver uses a local clock that is typically 16 times faster than the transmission rate (16x oversampling).
  • When it detects the leading edge of the Start bit (1 to 0 transition), it resets its internal counter.
  • It samples the start bit near its center, and then samples each subsequent data bit near its center. This keeps the receiver "in step" with the transmitter for the duration of that single character.
  • Because the clocks are independent, they might drift apart, which is why the character size is kept small (6-8 bits) and resynchronized at every Start bit.

Subtopic 4.3: Synchronous Serial Transmission

Step 1: The Core Concept & Analogy
The Engineering Problem:
Asynchronous transmission (with Start/Stop bits) is great for slow, cheap devices like old keyboards or mice. But if you want to send data at very high speeds over long distances (like a network cable), all those Start and Stop bits are a waste of bandwidth (overhead). Furthermore, at high speeds, it becomes very hard for the receiver's 16x clock trick to stay accurate. We need a faster, more efficient way to send large chunks of data.

The Real-World Analogy:
Think of a train.
Asynchronous (Start/Stop): You send a single passenger in a tiny taxi. You have to spend time telling the taxi to start, and it has to stop at the destination. This is inefficient for moving a large crowd.
Synchronous: You send a massive freight train with thousands of cars (blocks of data). There are no start/stop signals for every single passenger. Instead, the train has a powerful engine (the continuous timing signal) that keeps everything moving in perfect rhythm. The beginning and end of the train are marked with special flags (sync codes), but the entire block moves together.

Step 2: The Technical Definition

Synchronous Serial Transmission:

  • Data is transmitted in blocks (several hundreds or thousands of bits) rather than small characters.
  • There are no Start/Stop bits for every byte.
  • The receiver continuously recovers the timing information from the incoming signal itself (by observing the signal transitions) and adjusts the phase of its local clock.
  • The beginning and end of the data blocks are identified by special synchronization codes (e.g., a preamble pattern).
  • Advantages: Much higher speed and efficiency (less overhead).
  • Disadvantages: Requires more sophisticated hardware (clock recovery circuits) and is less suitable for simple, cheap devices.

Key Difference (Exam Point):
Asynchronous: Cheap, simple, uses Start/Stop bits, lower speeds, small characters.
Synchronous: Complex, efficient, uses blocks and clock recovery, very high speeds.

Subtopic 4.4: UART, USART, and Baud Rate

Step 1: The Core Concept & Analogy
The Engineering Problem:
We know how serial transmission works conceptually (bits moving one by one). But who actually does the conversion inside the computer? We need a specific piece of hardware to act as the translator between the parallel world of the CPU and the serial world of the outside devices. Also, we need a standard way to measure how fast this data is moving.

The Real-World Analogy:
UART/USART: Think of a translator at the United Nations. The CPU speaks "Parallel" (many words at once), and the device speaks "Serial" (one word at a time). The UART is the translator that converts one language to the other.
Baud Rate vs. Bit Rate: Think of a conveyor belt.
Baud Rate is how many items (symbols) are placed on the belt per second.
Bit Rate is how much information those items carry. If each item is just a single box (1 bit), then the baud rate equals the bit rate. But if each item is a pallet carrying 4 boxes (4 bits per symbol), then the bit rate is 4 times the baud rate.

Step 2: The Technical Definition

1. UART (Universal Asynchronous Receiver/Transmitter):

  • A standard serial interface intended for low-speed serial devices.
  • Performs serial-to-parallel and parallel-to-serial conversion.
  • Uses the asynchronous start-stop format. It automatically inserts Start and Stop bits during transmission and removes them during reception.

2. USART (Universal Synchronous/Asynchronous Receiver/Transmitter):

  • Supports both synchronous and asynchronous serial communication.
  • Can operate in asynchronous mode (like a UART) or synchronous mode.
  • Provides greater flexibility than a UART.

3. Baud Rate vs. Bit Rate:

  • Baud Rate: The number of symbols transmitted per second. It represents the number of times the state of the transmitted signal changes per second.
  • Bit Rate: The number of bits transmitted per second.
  • Binary Signaling (1 bit per symbol): Bit Rate = Baud Rate (e.g., 9600 baud = 9600 bits/s).
  • Multiple Bits per Symbol: Bit Rate = Baud Rate × bits per symbol (e.g., 1200 baud with 4 bits/symbol = 4800 bits/s).

Exam Point: Baud rate = symbols/second, not necessarily bits/second.

Subtopic 4.5: Basic Serial Interface & Standard UART Architecture

Step 1: The Core Concept & Analogy
The Engineering Problem:
We know the UART converts parallel to serial. But how does the CPU actually interact with it? The CPU needs to send data to it, check if it's ready, and receive data from it. We need a structured set of registers (small memory locations) inside the interface to manage this flow.

The Real-World Analogy:
Think of a post office counter.
DATAOUT (Transmitter Register): The drop-off box where you put your package (data) to be sent out.
DATAIN (Receiver Register): The pickup box where the postman leaves packages (data) that have arrived for you.
Status Register: A digital sign on the counter. It tells you: "Do you have mail to pick up?" or "Is the drop-off box full?"
Control Register: The settings panel. It lets you set the rules, like "Send packages in small boxes (7 data bits) or large boxes (8 data bits)," and "How fast should the delivery truck go (baud rate)?"

Step 2: The Technical Definition

A standard UART interface contains several key registers and shift registers to manage data flow:

1. Data Path (Shift Registers):

  • Input Path: The Input shift register receives data one bit at a time from the RX (Receive) line. After receiving 8 bits, it transfers them in parallel to the DATAIN register. The CPU reads DATAIN through the bus.
  • Output Path: The CPU writes data in parallel to the DATAOUT register. This data is transferred to the Output shift register, which shifts the bits out serially to the TX (Transmit) line.

2. Status Register:

  • Indicates the current state of the interface.
  • Flags: Data available (receiver has a full byte), Transmitter ready (ready to accept a new byte), and error flags (parity error, framing error).

3. Control Register:

  • Configures the UART.
  • Sets the baud rate (speed), number of data bits (e.g., 7 or 8), parity type (even/odd/none), and number of stop bits.

4. Chip Select (CS) and Register Select (RS):

  • CS: Activates the UART chip so the CPU can talk to it.
  • RS: Tells the UART which internal register the CPU wants to access (e.g., RS=0 for data, RS=1 for control/status).
